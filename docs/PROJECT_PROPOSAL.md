**项目简介与生态定位**

MoonExtract 从文本和字段定义出发，调用 OpenAI 兼容模型生成字段值，再要求模型给出逐字来源 quote。引擎把每个字段与原文档中的证据区间绑定，区分原始值、归一化值和证据文本，并处理重复来源、上下文消歧、来源缺失和字段冲突。它只证明字段值有原文支撑，不代替调用方判断语义真假。

现有精确匹配和 Unicode 码点区间是底层原语。本项目新增了字段定义、模型提示构造、结构化 claim 解析、证据绑定、上下文距离消歧、非重复字段冲突策略、重叠分块及可靠合并、OpenAI 兼容适配器和可复现评测。模型可以更换，证据解析和诊断语义保持在 MoonBit 内部。mooncakes 中已有通用 Aho-Corasick、模糊匹配和 Unicode 规范化包，因此本项目不重复实现这些通用算法，而是解决“模型输出如何成为可复核抽取记录”这一独立问题。

**预期使用场景**

1. **合同字段审核**：模型抽取甲方、乙方、金额和通知期限。系统输出每个字段的 verbatim quote 与码点区间；重复出现“30 日”时用“终止通知”上下文选择正确位置；金额原文为 `120,000 元`、模型返回 `120000 元` 时仍能绑定同一证据。
2. **客服工单分诊**：从服务名、严重级别、影响区域和根因中抽取字段。字段值可以经过格式归一化，但 quote 必须来自工单；模型给出文档中不存在的根因时，系统明确返回 `missing_source`，而不是把猜测当成证据。
3. **长文与编辑场景**：文档按重叠窗口分块，模型逐块返回 claim，系统去重并回到全文解析证据。文档内容变化后，同一 quote 可以被重新定位；无法继续成立的证据会暴露为缺失或歧义，供审核界面处理。

**核心功能与当前交付**

- `FieldDefinition`、`LlmClaim`、`Prompt`、`FieldResult`、`ExtractionReport` 和稳定诊断 JSON。
- OpenAI 兼容 Chat Completions 适配器，密钥只从环境变量读取。
- 注入式模型回调，网络适配与核心解析解耦，测试可使用录制模型。
- 解析带 Markdown 代码围栏的 JSON claim，并拒绝缺失字段、空值和不合法结构。
- 基于 quote 的全文证据绑定；上下文按距离消歧，距离相同时优先使用前置上下文。
- 重复来源、缺失来源、上下文不匹配、非重复字段冲突和必需字段缺失诊断。
- `Document::chunks_with_overlap` 重叠分块；跨块重复 claim 按字段、值、quote 和上下文字段去重。
- 合同审核与客服工单两组数据集，以及只按模型 `value` 做精确匹配的基线。
- 原生 CLI、离线 OpenAI 兼容协议服务和端到端评测命令。

**实现路径与验证**

模型响应先解析为 claim，再由引擎在完整文档中查找 quote。每个结果保存 `value`、`normalized_value`、`quote`、证据区间和状态；多解不静默取第一个，冲突不覆盖为单值。长文按码点窗口切分，保留重叠上下文，最后回到全文解析和去重。当前仓库共有 57 个 MoonBit 测试；合同数据集为 9/9，按 value 精确匹配的基线为 4/9；客服工单数据集为 11/11，基线为 8/11。两条业务链路都通过真实 HTTP 请求连接本地 OpenAI 兼容服务，验证了请求构造、响应解析、证据绑定和 JSON 输出。评测区间是人工标注的码点范围，且明确限定在提交数据语料，不宣称通用模型准确率。

验收以 `moon check --target all --no-mbti`、`moon test`、`moon run --target native cmd/eval -- datasets/contracts.json datasets/support-tickets.json` 和 CLI 示例可复现为准。下一阶段将补充真实模型供应商的对比、更多文档分布和规则计划执行，但不以增加外围功能替代核心语义。
